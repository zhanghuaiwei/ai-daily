# 不用写代码，用 llm openai endpoint add 注册任意兼容接口：这意味着什么？

> **导读**｜Simon Willison 的命令行工具 llm 发布了 0\.37 版本。本文教你用新增的 llm openai endpoint add 命令，将 Ollama 等 OpenAI 兼容接口注册到终端中，并演示如何将默认模型切换为价格减半的 gpt\-6\-luna。跟着敲命令即可复现。

---

如果你习惯在终端里调用大模型处理文本、查资料或做嵌入任务，Simon Willison 维护的开源命令行工具 llm 刚刚发布了 0\.37 版本。这次更新带来了一个新命令 llm openai endpoint add，让你能把本地或第三方支持 OpenAI 兼容接口的模型（比如 Ollama、vLLM）直接注册进来；同时，工具的默认模型被切换成了价格只有上一代一半的 gpt\-6\-luna。下面是具体的配置步骤。

## 前置条件与核心概念

开始之前，你需要准备好三样东西：一台能运行 Python 的设备、安装好的 llm 库（通过 pip 安装），以及一个正在运行的 OpenAI 兼容端点（例如本地启动的 Ollama）。整个过程不需要额外付费账号，成本取决于你调用的模型本身是否收费。

这里需要理解一个概念：OpenAI 兼容端点。你可以把它想象成一个标准的插座形状。只要你的本地模型服务或者第三方 API 提供的“插孔”符合这个标准形状，llm 工具就能直接插上去通电工作，而不需要针对每个模型单独写对接代码。

## 第一步：注册新的兼容端点

打开终端，输入 llm openai endpoint add 命令。根据 0\.37 版本的更新说明，这条命令专门用来配置使用 OpenAI 兼容端点的额外模型。执行后，按照终端提示输入你的端点地址和相关信息。

看到什么才算成功：命令执行完毕后，终端不会报错退出。此时该端点已经被写入 llm 的配置中。关于如何验证新端点是否已成功加入可用列表，公开信息没有提到具体的查看命令，需要自行尝试。

## 第二步：确认并使用新增模型

0\.37 版本同步加入了 gpt\-6\.1\-sol 和 gpt\-6\.1\-terra 两个新模型。完成端点注册后，你就可以在终端里直接指定这些模型来完成对话或生成任务。

官方文档未给出调用新模型的具体命令格式（例如是否需要加特定参数前缀），这部分需要自行尝试。但核心逻辑是：只要端点注册成功，llm 就能把请求路由过去。

## 第三步：切换默认模型为 gpt\-6\-luna

如果你之前没有手动设置过自己的默认模型，llm 0\.37 会自动将默认模型切换为 gpt\-6\-luna。这个模型的价格是上一代默认模型 gpt\-5\.6\-luna 的一半。这意味着你在终端里不指定模型直接发起请求时，走的将是更便宜的新通道。

看到什么才算成功：当你像往常一样在终端向 llm 发送一段文字请求时，如果返回结果正常且后台计费（若有）按 gpt\-6\-luna 的标准扣除，就说明默认模型已经生效。如果你之前手动锁定过其他默认模型，则不受此自动切换影响，需要自行调整。

## 补充：嵌入任务的格式变化

如果你的工作流涉及嵌入（Embeddings）任务，0\.37 版本做了一个底层改动：现在支持不同的二进制内容拥有不同的 content\-type。这是因为像 Gemini Embedding 2 这样的模型，不仅能处理文本，还能处理音频、图像和视频。如果你只用文本做嵌入，这个变化对你没有直接影响；如果需要处理多媒体文件，这是必要的前置支持。

---

这套做法适合经常需要在终端里快速调用不同大模型的开发者，尤其是那些同时在云端 API 和本地 Ollama 之间切换的人。如果你只在网页聊天框里使用 AI，或者完全依赖某个 IDE 里的内置插件，那么特意去配置命令行工具并不划算。下一步，你可以尝试用新注册的端点跑一些实际的文本处理脚本，或者关注 llm 库后续是否会开放更多针对非 OpenAI 格式的原生命令。
