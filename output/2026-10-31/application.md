# 在 Slack 里发一句话，让 AI 自动写代码生成品牌海报和视频：没那么简单

> **导读**｜LangChain 开源了其内部使用的 Content Studio 设计智能体。本文拆解如何克隆仓库、配置品牌资产，并在 Slack 中通过一句提示词触发 Agent，自动生成视频和海报等视觉素材。

---

每次做产品发布或活动推广，设计师总要被各种海报、PPT 封面和视频素材淹没。LangChain 团队把解决这个问题的内部工具 Content Studio 开源了——你在 Slack 频道里发一句话描述需求，它就能自动产出符合品牌规范的视觉文件。跟着这篇教程，你可以把这套工作流跑通在自己的 Slack 里。

## 前置条件与准备工作

Content Studio 是一个基于 LangChain 框架构建的设计智能体，所有生成的视觉素材底层都是代码（如 HTML、CSS、图表规范和动画时间轴）。你需要准备三样东西：一个可以安装应用的 Slack 工作区；一台能运行 Git 的电脑用于克隆开源仓库；以及你们公司的品牌规范文件，包括品牌色值（brand tokens）、字体文件和特定的设计技能说明。

部署环节需要用到 Managed Deep Agents 服务。根据官方披露，该服务提供托管的 LangSmith Sandbox（沙盒环境）、Slack 集成、工具管理、作用域内存和任务调度。目前公开信息尚未提到该服务的具体定价，但官方给出的参考数据是：迁移到该服务后，他们单次请求的模型调用成本中位数降到了约 0\.5 美元。

## 第一步：获取代码并注入品牌规范

前往 LangChain 官方提供的开源仓库地址，使用 Git 将项目克隆到本地。这是整个流程的起点，官方明确表示“你可以 fork 它”。

克隆完成后，找到项目中存放配置的目录，将你们公司的品牌色值、字体文件和自定义的设计技能（skills）替换进去。这一步至关重要。AI 模型本身擅长写代码和执行排版，但如果没有你的上下文，它会倾向于输出最常见的通用样式。把你的设计原则写进 Agent 的技能库和检查项里，就是给它植入“品味”，让它知道什么对你们公司来说是“好设计”。

## 第二步：部署到 Slack 并理解沙盒机制

通过 Managed Deep Agents 将修改后的代码部署到你团队的 Slack 工作区。部署成功后，Agent 会作为一个应用存在于你的 Slack 中。

这里需要理解一个核心概念：沙盒（Sandbox）。当有人在 Slack 线程里向 Agent 提出需求时，系统会为这个线程单独分配一个沙盒环境。你可以把它想象成给 Agent 临时开了一台专属电脑。在这台“电脑”里，Agent 可以在多轮对话之间保留项目进度，同时调用视频引擎、图像工具和共享画布，并且能自己检查渲染出来的结果。官方文档未给出沙盒的具体资源上限，这部分需要自行尝试。

## 第三步：发起请求与多人协作审批

在 Slack 中找到 Agent 所在的频道或拉入线程，输入你的需求提示词，并附上相关的背景内容或简报（briefs）。比如要求它制作一段产品宣传视频或一张社交媒体配图。

对于耗时较长的大型任务，Agent 会在后台异步运行子任务。此时，当前的 Slack 线程界面会显示它的执行计划、实时进度，并且在最终文件发出前会弹出一个审批确认。在这个阶段，团队里的任何人都可以在中途介入，调整 Agent 的方向。这种多人协作体验是专门为长时间运行的任务设计的。

看到什么才算成功？当你在线程中收到由代码渲染出的成品文件（如视频、幻灯片或图片），且视觉风格符合你之前配置的品牌规范时，就说明整个链路跑通了。

## 维护建议：删掉过时的规则

官方团队分享了一个反直觉的经验：随着底层大模型能力的提升，你早期为了让它避开某些错误而写的变通规则（workarounds）会过期。你应该长期保留的是核心的设计原则，而那些为了弥补模型弱点打的补丁，需要在模型迭代后及时删除，否则反而会限制它的表现。

---

这套方案适合有明确品牌规范、且日常有大量重复性视觉物料需求的团队，尤其是习惯使用 Slack 办公的公司。如果你的团队只有偶尔一两张图的需求，或者没有精力整理品牌色值和字体文件去配置仓库，那么直接用现成的图像生成工具会更省事。跑通基础流程后，下一步可以尝试往仓库里添加更复杂的自定义技能，让 Agent 处理特定业务场景下的图表或交互式 UI 还原。
